# 任务进度页设计（Progress Page）

> 状态：设计评审稿（v2，参考即梦交互重设计）
> 关联：`manual_mode_PRD.md`（v6.0 手动模式）、`implementation_plan.md`
> 目标：把"任务进度"从常驻底部面板升级为**独立页面**，首次执行与任务列表进入**复用同一页面**。
> 交互范式：**左侧环节状态列表 + 右侧逐步追加的产物流 + 暂停操作就近锚定最新产物卡片**（即梦式）。

---

## 1. 背景与问题

### 1.1 现状

- `ProgressPanel` 常驻 `App.vue` 底部，由 `progressVisible` 控制显隐。
- 首次执行：表单提交成功后直接进入进度面板（与创建页混在同一视口）。
- 任务列表打开：`viewTask` / `viewRunningTask` / `resumeTask` 都汇入 `useProgress`，渲染同一个 `ProgressPanel`——**入口已统一，但载体不是页面**。
- 暂停审查时 `CheckpointDetail` 的产物区与操作区垂直分离，产物多时操作被推出一屏之外。

### 1.2 设计目标（即梦范式）

1. 进度成为**独立全屏页面**，首次执行 / 列表进入 / 刷新恢复 三个场景走同一个页面。
2. **左栏独立展示所有环节与状态**：全部环节垂直排列、状态一目了然，支持点击定位右侧产物。
3. **主工作台逐步追加**：每个环节的产物生成后以卡片形式追加到工作台（feed 式），已完成环节卡片自动折叠，工作台只聚焦"进行中 + 最新"。
4. **暂停时，操作交互就近锚定在最新产物卡片附近**：用户在哪看到问题，就在哪操作，不另设远离产物的操作区。
5. 零后端改动、不引入新依赖。

---

## 2. 实现方式：视图状态机 + URL Hash 同步

| 方案 | 说明 | 结论 |
|------|------|------|
| A. 引入 vue-router | 需处理 `base=/static/` + FastAPI 静态伺服 fallback，改动面大 | 不选 |
| **B. 视图状态机 + hash（推荐）** | `mainTab: 'create' \| 'list' \| 'progress'`；进入进度页写 `#/progress/<taskId>`，刷新/直达时从 hash 恢复 | **选用** |

### 2.1 导航状态

```ts
appState.view = 'create' | 'list' | 'progress'   // 顶层视图
appState.progressTaskId: string | null           // 进度页当前任务
appState.progressOrigin: 'create' | 'list'       // 返回目标
```

- hash 同步：进入 `location.hash = '#/progress/' + taskId`；返回写回来源视图 hash。
- 启动解析 hash：`#/progress/<id>` → 直接进入进度页并恢复任务（按状态决定轮询）。
- 返回：`progressOrigin` 决定回创建页还是列表；`unmountProgressPage` 停止一切轮询。

## 3. 页面布局（即梦式）

### 3.1 宽屏（≥1024px）

```
┌───────────────────────────────────────────────────────────────────────┐
│ ◀ 返回   🎥 任务名(task_id)   类型·模式徽标   状态   [⚡切自动] [■停止] │ ← 顶部任务栏 (sticky)
├────────────────┬──────────────────────────────────────────────────────┤
│ 环节列表        │ 主工作台（产物流，逐步追加）                           │
│ (sticky 230px) │ ┌─ 状态区 ──────────────────────────────────────────┐ │
│  ○ 初始化      │ │  进度条 % + 当前消息 / 失败横幅 / 完成提示          │ │
│  ✓ 剧本        │ └──────────────────────────────────────────────────┘ │
│  ✓ 分镜        │ ┌─ 环节卡片：场景 1 ────────────────────────────────┐ │
│  ⏸ 参考图 ◀当前 │ │  🖼️ 缩略图    [🔁] [✎AI改] [📋] [🗑]             │ │
│  ○ 视频        │ └──────────────────────────────────────────────────┘ │
│  ○ 音频        │ ┌─ 环节卡片：场景 2 ────────────────────────────────┐ │
│  ○ 字幕        │ │  🖼️ 缩略图                                        │ │
│  ○ 拼接        │ └──────────────────────────────────────────────────┘ │
│                │ ╔═ ⏸ 暂停审查 · 参考图（最新产物）════════════════════╗ │
│                │ ║  🖼️ 角色参考图（大图）                             ║ │
│                │ ║  📋 复制路径  [🔁 重新生成]                        ║ │
│                │ ║  ────────────────────────────────────────────     ║ │
│                │ ║  [AI 帮我改] [我自己改] [找 Agent]                 ║ │
│                │ ║  ✎ 输入修改请求 → ⚠ 影响提示 → [✔ 批准继续 ▶]      ║ │
│                │ ╚════════════════════════════════════════════════════╝ │
│                │  ··· 后续环节产物继续追加 ···                          │
│                │ ┌─ 结果视频 ────────────────────────────────────────┐ │
│                │ └──────────────────────────────────────────────────┘ │
└────────────────┴──────────────────────────────────────────────────────┘
```

### 3.2 移动端（<1024px）：单列堆叠

- 顶部任务栏固定（返回 + 任务名 + 停止）。
- 环节列表退化为**横向滚动胶囊条**（可点击定位）。
- 产物卡片单列追加；暂停审查区直接出现在最新产物卡片**正下方**，操作按钮自然贴近产物。
- 结果视频在末尾。

### 3.3 布局要点

1. **顶部任务栏 sticky**：返回、任务信息（名/ID/类型/模式徽标/状态）、停止、切自动。
2. **左栏环节列表 sticky**（即梦式）：
   - 全部环节垂直排列，状态图标：`○ 排队 / ◉ 生成中(呼吸) / ✓ 完成 / ✗ 失败 / ⏸ 等待用户`；
   - 当前环节高亮 + 右侧指示条；
   - 点击已完成的环节 → 滚动定位到右侧对应产物卡片；
   - 所有长视频任务类型（creative/manuscript/anchor/poetry）的环节在此统一呈现。
3. **主工作台 = 逐步追加的产物流**：
   - 每个环节产物生成后**追加**一张卡片，按执行顺序排列（feed 式，非固定网格）；
   - 卡片包含：环节名 + 缩略图/预览 + 状态；
   - **已完成且已通过的环节卡片自动折叠**为一行（标题 + 缩略图小图 + 状态），避免工作台无限增长；点击可展开查看；
   - 图片点击放大（复用现有 image modal）、视频内联播放、文本/JSON 点击展开预览。
4. **暂停审查区（关键交互）**：紧跟最新产物卡片之后渲染，形成"产物 → 操作"的连续视觉单元：
   - 顶部是该检查点产物的大图/大预览（即刚生成的"新产物"）；
   - 产物操作直接贴在其上：`复制路径 / 重新生成`；
   - 下方三通道（AI 帮我改 / 我自己改 / 找 Agent）切换，各自内联展开；
   - 选中/输入修改后展示影响提示（`/impact`），确认后 `[✔ 批准继续 ▶]`；
   - 整个审查区**就地**出现，不离场、不跳转。

## 5. 状态流

```
首次执行
  表单提交成功 ──→ view='progress', origin='create', hash=#/progress/<id>
                  ──→ ProgressPage.mount: showProgress + startPolling

任务列表进入
  查看(已完成) ──→ view='progress', origin='list' ──→ 加载产物流 + 结果视频（不轮询）
  继续(待执行) ──→ resumeTask ──→ 同上（轮询）
  查看进度(运行中) ──→ viewRunningTask ──→ 同上（轮询）

刷新 / 直达
  启动解析 hash=#/progress/<id> ──→ view='progress' ──→ 恢复任务（按状态决定轮询）

暂停等待
  poll 检测 pending+awaiting_user
    ──→ 左侧环节标记 ⏸、高亮当前环节
    ──→ 产物流追加最新产物卡片
    ──→ 紧跟其后渲染"暂停审查区"（就近操作）
    ──→ 批准后 setRunning + startPolling，审查区消失、产物卡片折叠

返回
  点击返回 ──→ 停轮询 + 清理 currentTaskId ──→ view=origin（create|list）
```

### 5.1 轮询生命周期

- 进入进度页：仅当任务 `running/queued` 才 `startPolling`；暂停（`pending`）时不轮询；
- 轮询期间每次拉取产物列表，**按执行顺序 diff 追加**新卡片（新产物出现即追加在流末尾）；
- 审查区批准 / 重生成 / 切自动后：`setRunning + startPolling`；
- 完成 / 失败：停止轮询，展示结果区；
- 返回：`unmountProgressPage` 停止一切轮询。

## 6. 验收标准

1. 首次创建任务后自动进入进度页，URL 变为 `#/progress/<taskId>`。
2. 任务列表的「查看 / 继续 / 查看进度」均进入同一进度页，返回回到列表。
3. 刷新进度页 URL 后恢复原任务视图与产物流。
4. 左栏展示全部环节与状态；完成环节点击可定位到右侧产物卡片。
5. 主工作台产物逐步追加：新产物出现在流末尾，已通过环节折叠为一行。
6. 暂停时审查区紧贴最新产物卡片：三通道操作、影响提示、批准继续流程正常。
7. 移动端单列可用，环节列表为横向胶囊。
8. 六种任务类型（simple/creative/manuscript/anchor/poetry/image）进度展示正常。
9. 全量 i18n 无缺 key（`npm run build` 无警告，19 语言文案齐全）。
